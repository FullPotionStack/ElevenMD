# External File Sync Implementation Plan

> Execute inline with superpowers:executing-plans and TDD; one independent final review.

**Goal:** Make open tabs accurately reflect disk state without losing editor or external changes.
**Spec:** docs/superpowers/specs/2026-10-18-file-sync-design.md
**Architecture:** Main-owned inspection/revision/resolve APIs; directory-watch and metadata polling hints; renderer reconciliation and safe comparison dialog. Preserve a previous buffer in the private session.
**Constraints:** No new dependencies; existing 10 MiB file/100 MiB session limits; opaque IDs only; native authorization for destructive writes; bump 0.3.11; never use owner documents as test fixtures.

## Tasks
1. Document inspection and resolution (`electron/files.cjs`, `tests/file-sync.test.mjs`): RED for same/change/delete/unreadable, stale revision, cancellation, overwrite/recreate and native locate; implement serialized operations retaining pre-save hash checks; full unit suite GREEN.
2. Monitor and IPC (`electron/file-monitor.cjs`, main/preload, session): RED for atomic replacement and watcher disposal plus previous-buffer persistence/validation; wire startup/focus/watch hints and trusted main-frame APIs; update preload contract; unit suite GREEN.
3. Renderer (`src/file-sync.js`, `src/line-diff.js`, main/style): RED tests for clean reload, edited conflict, changed-during-approval rejection, missing status/recreate, previous recovery, escaped/bounded diff; implement nonmodal banner and comparison/merge actions; browser and unit suites GREEN.
4. Delivery: real desktop fixture edits disk while app open, restarts with conflict/missing, tests reviewed revision/restore; independent security/data-loss review; fix required findings with RED→GREEN. Version 0.3.11, production package/installer, native CI, push/release and authorized in-place owner upgrade. Read back remote writes and actual installed version/session/UI.

## Review focus
- Edits while reload IPC is in flight: keep current text and show conflict.
- Atomic file replacement or absent parent directory: no missed permanent state; no watcher crash.
- Further disk edit during native confirmation: reject stale resolution without writing.
- Missing or unreadable file on restore: preserve text and baseline, do not claim Saved.
- Large/hostile diff text: bounded work and no executable HTML.

Each task: write regression, observe failure, implement, run focused/full tests, record result and commit. Existing service save serialization and final hash checks remain intact.
